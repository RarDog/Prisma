# Манга + провайдеры: стабильность и производительность

## Провайдеры — стабильность

1. **Фикс бага вытеснения Dio-клиентов** (`provider_factory.dart`): кэш ограничен 8 клиентами, а сидов 19 конфигов — при полном прогоне (`allProviders()`, проверка здоровья всех) провайдеры из той же пачки теряют своих клиентов, которые закрываются LRU-вытеснением, и все их запросы падают. Решение: потолок 8 → 32 + карта `id → ключ`, чтобы при пересоздании провайдера с новым конфигом старый клиент закрывался адресно, а не по вытеснению.
2. **Классификация ошибок ретрая** (`provider_manager._isRetryableError`): сейчас любой не-Dio `AppException` считается «повторяемым» — в том числе `BadResponseException`/`ProviderUnavailableException` (битый ответ, Cloudflare-блок), которые ретраить бессмысленно. Детерминированные AppException'ы → non-retryable.
3. **Pawchive перестаёт глотать ошибки**: `searchPosts` возвращает `const []` на любую ошибку — мёртвый провайдер неотличим от «нет результатов», пагинация молча заканчивается. Ретроу.
4. **e621-троттл без гонки**: статический 500ms-троттл читается-пишется без синхронизации — параллельные поиски проскакивают пачкой. Цепочка Future-замыканий (последовательная очередь).
5. **Хрупкие скраперы**: realbooru_html — ограничить жадные `[\s\S]*?`-блоки (`{0,4000}?`), обернуть `jsonDecode` в autocomplete try/catch; rule34_us — health-маркер принимает оба написания (`thumbail-container`/`thumbnail-container`).
6. **Soft-retry уважает отмену**: в отложенный ретрай передаётся cancelToken исходного поиска — если пользователь уже ушёл, ретрай не выполняется.

## Провайдеры — производительность

7. **TTL-кэш активных провайдеров в менеджере** (10 сек, инвалидация на CRUD — как у уже существующего кэша подсказок): каждый `getPost`/`getMediaHeaders`/`getComments` сейчас делает чтение БД + до 19 `factory.create()`.
8. **Парсинг HTML в изоляте**: списки xvideos, realbooru, fapello (страницы по 100–500 КБ регулярок на UI-потоке) → `Isolate.run` через top-level чистые функции.
9. **Мемоизация `mediaHeaders`** на экземпляре провайдера (danbooru и др. строят новую map на каждый вызов).
10. **MangaDex-подсказки параллельно**: `/author` и `/manga` идут последовательно на каждое нажатие — `Future.wait`.

## Вкладка Манга — производительность

11. **`memCacheWidth` на обложки** — самый жирный выигрыш: `manga_card`, `manga_library_card`, `manga_horizontal_list` декодируют 512px JPEG в полном разрешении; ограничить до ~480px.
12. **`cacheWidth` для офлайн-страниц ридера**: `Image.file` без `cacheWidth` декодирует страницу целиком, тогда как сетевые страницы уже клампятся до 1080–1920px.

## Вкладка Манга — надёжность и UX

13. **Ошибка на экране манги**: `_loadMangaData` глотает все ошибки — при неудаче экран остаётся пустым. Полноценное ErrorView с retry для основных данных; retry-кнопка на ошибке в Library; «очистить поиск» в пустом каталоге.
14. **Параллельная проверка обновлений библиотеки**: `checkForUpdates` ходит по записям строго последовательно (50 записей = 50 запросов подряд) → воркер-пул с concurrency 4.
15. **Авто-проверка обновлений** один раз за сессию при первом открытии вкладки Library (сейчас только вручную).
16. **Типографика novel-ридера сохраняется** в настройки (сейчас сбрасывается каждый запуск).

## Не делаю в этом заходе (крупные фичи — отдельно)
Очередь загрузок глав с паузой/возобновлением и UI прогресса, история поисковых запросов манги, статус-бейджи на карточках каталога, ручной evict дальних страниц ридера, перенос `_isRetryableError`-логики внутрь провайдеров, cross-page дедуп ленты.
